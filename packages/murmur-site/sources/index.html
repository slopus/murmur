Encrypted sessions that survive the connection.

Murmur is a browser-safe TypeScript library for stateful MLS sessions. Durable cryptographic state lives in application storage. The relay is a bounded, disposable delivery buffer for ciphertext it cannot read.

The model

Four durable transitions.

01

Identity

One 32-byte Ed25519 public key names a device. Signing and X25519 agreement derive from one protected root.

02

KeyPackage

one-use MLS admission material is stored durably before its public bytes leave the client.

03

Session

A Welcome creates bounded pending state. Activation releases buffered application updates.

04

Synchronization

Protocol progress and exact outboxes persist before relay acknowledgement or application effects.

Trust boundary

A queue, never a conversation server.

The relay sees

  • sender and recipient public identities
  • exact multicast fanout
  • delivery sizes, timing, TTL, and queue progress

The relay never receives

  • identity roots
  • MLS epochs
  • application plaintext

The relay can delay, drop, replay, or reorder work across inboxes. It cannot decrypt MLS content or forge authenticated session traffic. Murmur protects content, not communication metadata.

Cryptography

Named primitives, narrow claims.

The implemented suite is 0x0001: DHKEM(X25519, HKDF-SHA-256), HKDF-SHA-256, AES-128-GCM, Ed25519, BasicCredential, and SHA-256. Account provisioning also uses AES-256-GCM.

  • RFC 9420 (MLS)
  • RFC 9180 (HPKE)
  • RFC 7748 (X25519)
  • RFC 5869 (HKDF)
  • RFC 8032 (Ed25519)
  • @noble/curves
  • @noble/hashes
  • @noble/ciphers

Murmur has not received an independent security audit. Implementing the active protocol subset is not a claim of complete RFC feature coverage.

Application boundary

Typed services, opaque bytes.

A MurmurService claims new sessions with onNewSession and receives routed updates through onUpdate. The global batch contains only unclaimed application work, so do not apply the update a second time. 

const member = await bob.createKeyPackage();
const session = await alice.createSession({
    descriptor: new TextEncoder().encode("chat.v1"),
    members: [member],
});
const client = await MurmurClient.open({
    relay,
    store,
    services: [{ id: "notes.v1", service }],
});

Run it

Library state here. Queue state there.

pnpm add @slopus/murmur

MURMUR_RELAY_STORE=sqlite \
MURMUR_RELAY_DB=./data/murmur-relay.sqlite \
pnpm --filter @slopus/murmur-relay start

Production deployments require TLS termination, durable storage, bounded ingress, and non-Sybil admission control. There is no hosted public relay and no history or recovery from relay storage.
